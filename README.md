# WhisperDesk — Local Speech-to-Action Utility

A lightweight tool that transcribes microphone audio and turns spoken notes
into structured text, built to compare model size vs. speed/accuracy
(Task 3) and live vs. batched UI patterns (Task 2).

## Structure

```
├── README.md
├── LICENSE
├── requirements.txt
├── benchmarks/
│   ├── benchmark.py        # Task 3 evaluation harness
│   ├── ground_truth.json   # you fill this in with the 10 samples' true text
│   ├── test_audio/         # put your 10 wav/mp3 samples here
│   └── results.json        # generated by benchmark.py
├── client/
│   ├── index.html          # A/B study UI
│   └── app.js
├── engine/
│   └── transcriber.py      # shared faster-whisper wrapper
└── server.py                # Flask backend used by client/
```

## Setup

```bash
pip install -r requirements.txt
```

## Task 3 — Run the benchmark first

1. Drop 10 audio clips (5–15s each) into `benchmarks/test_audio/`.
2. Create `benchmarks/ground_truth.json`:
   ```json
   { "sample1.wav": "exact text you said", "sample2.wav": "..." }
   ```
3. Run:
   ```bash
   python benchmarks/benchmark.py
   ```
4. Paste the printed table below, and update `WINNING_MODEL` in `server.py`
   to whichever approach wins.

### Results

| Metric | Approach A (tiny.en) | Approach B (base.en) | Approach C (small.en) |
|---|---|---|---|
| P95 Latency (RTF) | 0.140 | 0.195 | 0.637 |
| Avg WER (%) | 17.06 | 15.01 | 14.39 |
| Peak RAM (MB) | 22.0 | 15.4 | 15.4 |

**Conclusion:** base.en offers the best practical trade-off for consumer hardware. Moving from tiny.en to base.en cuts word error rate by roughly 2 percentage points while still running well within the real-time target (RTF 0.195, versus the <0.3 goal). Moving further to small.en only shaves another 0.6 points off WER, at more than 3x the latency — a poor trade for a local, responsiveness-sensitive tool. Note: the RAM figures above are measured via Python-level `tracemalloc` and likely understate true memory use, since the core transcription engine runs in a native (non-Python) library that this method can't fully see — a more accurate measurement would need a process-level tool like `psutil`'s RSS tracking instead.

## Task 2 — A/B user study

1. Start the backend: `python server.py`
2. Serve the client: `cd client && python -m http.server 8000`
3. Send 5 participants `http://localhost:8000?version=A` and 5 participants
   `http://localhost:8000?version=B`.
4. Record results in `USER_STUDY.md` (template provided).
